# Architecture

## Codebase layout

| Path | Responsibility |
| --- | --- |
| `src/routes/__root.tsx` | App shell: `<html>` classes, global head metadata, stylesheets, favicon, Web Awesome loader, error and 404 boundaries. |
| `src/routes/index.tsx` | The single public page. Terminal UI, command parser, game state, per-page SEO metadata and JSON-LD. |
| `src/routes/routeTree.gen.ts` (`src/routeTree.gen.ts`) | Generated by the TanStack Router plugin. Never edit by hand. |
| `src/lib/game-data.ts` | **Single source of CV content**: `PLAYER`, `ROOMS`, `EXAMINE`, `HELP`, `MAP_POS`, `MAP_LINKS`. Update the CV here. |
| `src/components/MapPanel.tsx` | SVG map overlay: visited-room reveal, connection lines, current-room pulse, click-to-travel. |
| `src/styles.css` | Tailwind v4 entry plus the hand-written CRT theme (scan lines, flicker, glow, `.pdf-key`). |
| `src/design-system/font-awsome-web-awesome-171158/` | Vendored Web Awesome copy (components, theme, vendor bundle). Do not edit. |
| `src/components/ui/`, `src/hooks/`, `src/lib/utils.ts` | shadcn-style primitives and helpers from the starter template. |
| `src/start.ts`, `src/server.ts`, `src/lib/error-page.ts` | Server entry and SSR error wrapper. |
| `scripts/copy-static-output.mjs` | Post-build step: copies `.output/public` to `dist/client` when present, otherwise no-ops. |
| `public/` | Static assets served verbatim: `favicon.png`, `Mike_Demopoulos_CV.pdf`, `robots.txt`, `sitemap.xml`, `_redirects`. |
| `vite.config.ts` | Build config; declares the prerendered routes. |

## Design decisions

**Content is data, not markup.** Every room, description, examinable object and
map coordinate lives in `src/lib/game-data.ts`. Refreshing the CV means editing
that one file; the engine and map derive everything else (`MAP_LINKS` is
computed from room exits).

**State is local React state.** The game keeps its history, current room,
visited set and inventory in `useState` inside `src/routes/index.tsx`. There is
no global store, no context, and deliberately **no URL search-param state** —
the game is a transient session, and keeping the URL clean keeps the single
canonical URL simple for search engines. Any future shareable state (e.g. a
"resume from room X" link) should be added as a validated route search schema
rather than ad-hoc `window.location` parsing.

**Client vs server boundary.** The site is prerendered: the server renders the
shell, heading structure and initial room text so crawlers see real content.
All interactivity (keyboard input, command evaluation, map updates) happens
after hydration. Nothing reads cookies, headers or per-user data, which is what
makes a fully static build safe.

**Styling.** Tailwind v4 handles layout; the CRT look is bespoke CSS because the
design system has no equivalent. The terminal's buttons and links intentionally
stay hand-styled rather than using `WaButton` — the retro look is the product.
Design-system components used elsewhere must keep their own skin.

**SEO.** Metadata is declared in route `head()` so it is baked into the
prerendered HTML: title, description, canonical, OG/Twitter tags on the index
route, and ProfilePage + Person JSON-LD. `sitemap.xml` is a static file, not a
server route.

## Gotchas & lessons learned

- **Web Awesome must load client-side.** `<WebAwesomeLoader />` (mounted in
  `__root.tsx`) dynamically imports the vendor bundle after hydration. Never
  import Web Awesome component modules at module scope of SSR-evaluated code —
  they touch `document` and crash the server render.
- **Prerender crawling must stay off.** `vite.config.ts` pins
  `crawlLinks: false` and `failOnError: false`. Lovable's own build forces these,
  but external CI does not: with crawling on, the prerenderer followed the
  "PDF CV" link, tried to render `Mike_Demopoulos_CV.pdf` as a page, got a 404
  and failed the build. Every prerendered route must be listed explicitly under
  `tanstackStart.pages`.
- **`routeTree.gen.ts` is generated.** Add or rename files under `src/routes/`;
  never hand-edit the generated tree, and never cast a route path to silence a
  `FileRoutesByPath` error — create the missing route file instead.
- **Build output location.** This template writes directly to `dist/`
  (`dist/client`, `dist/server`), so `scripts/copy-static-output.mjs` usually
  logs that `.output/public` is missing and skips. That is expected; the script
  exists for toolchain versions that emit the Nitro layout.
- **Edge worker constraints.** Any future server code runs on Cloudflare
  Workers: no `child_process`, `sharp`, native addons, or module-scope timers
  and I/O. Read `process.env` inside handlers, not at module scope.
- **Hydration safety.** Do not read `localStorage` or `window` in `useState`
  initializers; use `useEffect` so server and client markup match.
- **Bundle size.** The design-system chunk is large (~790 kB client) and
  triggers a Vite chunk-size warning. Harmless today, but it is the first thing
  to trim if load time becomes a concern.
